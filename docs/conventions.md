# Repository Conventions

## Day folders

Use the pattern `day-XX-short-topic`. Keep source code, tests, and a short
README together when a lesson needs more than one file.

## Commits

Use imperative, focused commit messages:

```text
Add JavaScript array transformation practice
```

Do not combine unrelated days or cleanup work in one commit.

## Project quality bar

As the stack grows, each project should include:

- A problem statement and acceptance criteria
- Clear setup instructions
- Environment variable documentation in `.env.example`
- Input validation and explicit error handling
- Automated tests for important behavior
- Accessibility and responsive UI checks
- A short architecture and deployment note
